# Migration Guide

This document covers migration from older environment-variable-only vexcoder
setups to the current config-file-plus-environment model. `vex migrate config`
is a convenience generator for the mappings listed here.

---

## Legacy variable to current variable mapping

| Legacy variable | Legacy value | Current replacement | Notes |
| :--- | :--- | :--- | :--- |
| `VEX_API_PROTOCOL` | legacy messages value | `model_protocol = "messages-v1"` | |
| `VEX_API_PROTOCOL` | legacy chat value | `model_protocol = "chat-compat"` | |
| `VEX_STRUCTURED_TOOL_PROTOCOL` | `on` | `tool_call_mode = "structured"` | |
| `VEX_STRUCTURED_TOOL_PROTOCOL` | `off` | `tool_call_mode = "tagged-fallback"` | |
| `VEX_MODEL_URL` | full endpoint path | `model_url` | Strip `/v1/messages` or `/v1/chat/completions` suffix |

These are vexcoder's own legacy variable names. No third-party tool migration
is performed automatically.

---

## Using `vex migrate config`

`vex migrate config` reads the legacy variables from the environment and
writes a `.vex/config.toml` fragment to stdout by default. `--output <path>`
writes the fragment to a file instead. It is non-destructive unless an explicit
output path is provided.

```sh
# Preview
vex migrate config

# Write to file directly
vex migrate config --output .vex/config.toml

# Append to existing config
vex migrate config >> .vex/config.toml
```

Example output when `VEX_API_PROTOCOL=<legacy messages value> VEX_STRUCTURED_TOOL_PROTOCOL=on`:

```toml
# generated by vex migrate config
# apply this fragment to .vex/config.toml or ~/.config/vex/config.toml
model_protocol = "messages-v1"
tool_call_mode = "structured"
```

## Configuration file locations

VexCoder resolves configuration from five layers, highest priority first:

| Priority | Source | Path |
| :--- | :--- | :--- |
| 1 | Environment variables | supported `VEX_*` variables |
| 2 | Repo-local config | `.vex/config.toml` (nearest ancestor `.vex/`) |
| 3 | User config | `~/.config/vex/config.toml` (XDG) or `~/.vex/config.toml` |
| 4 | System config | `/etc/vex/config.toml` |
| 5 | Compiled defaults | Inline defaults |

TOML key names mirror the active runtime keys in snake_case. `VEX_MODEL_TOKEN`
is never read from any config file. It remains environment-only. `notes_path`
is user-config only.

---

## Current config TOML key reference

| Key | Layers | Purpose | Notes |
| :--- | :--- | :--- | :--- |
| `model_profile` | repo, user, system | Selects a repo-tracked profile under `models/` | Relative paths resolve from the workspace repo root when available |
| `max_memory_tokens` | repo, user, system | Token budget for user notes injection | Mirrors `VEX_MAX_MEMORY_TOKENS`; default `2048` |
| `max_project_instructions_tokens` | repo, user, system | Token budget for project instructions injection | Mirrors `VEX_MAX_PROJECT_INSTRUCTIONS_TOKENS`; default `4096` |
| `notes_path` | user only | Explicit path to the notes file used for memory injection | Rejected in repo-local config |

## Current environment variable reference

| Variable | Purpose | Default |
| :--- | :--- | :--- |
| `VEX_MODEL_URL` | Base URL of the model API endpoint | `http://localhost:11434/v1` |
| `VEX_MODEL_NAME` | Model identifier string | `local/default` |
| `VEX_MODEL_TOKEN` | API bearer token, environment only | (none) |
| `VEX_MODEL_BACKEND` | `local-runtime` or `api-server` | inferred from URL |
| `VEX_MODEL_PROTOCOL` | `messages-v1` or `chat-compat` | inferred from URL |
| `VEX_TOOL_CALL_MODE` | `structured` or `tagged-fallback` | inferred from endpoint |
| `VEX_MODEL_PROFILE` | Repo-tracked profile path such as `models/api-structured.toml` | backend default profile |
| `VEX_MODEL_HEADERS_JSON` | Extra request headers as a JSON object | (none) |
| `VEX_WORKDIR` | Working directory for tool execution | `$PWD` |
| `VEX_MAX_MEMORY_TOKENS` | Token budget for user notes injection | `2048` |
| `VEX_MAX_PROJECT_INSTRUCTIONS_TOKENS` | Token budget for project instructions injection | `4096` |

## Project instructions file

vexcoder searches for a project instructions file at session start in this
order: `.vex/AGENTS.md`, `AGENTS.md`, `.vex/PROJECT.md`. The first file found
is read and prepended to the system prompt within the configured token budget
(`VEX_MAX_PROJECT_INSTRUCTIONS_TOKENS`, default 4096 estimated tokens).

If the file exceeds the budget, it is skipped and a warning is written to
stderr. The session continues. A budget overflow does not fail startup.

The loaded path is shown in the TUI session header as `inst:<path>`, or
`inst:none` when no file was found.

---

## Notes on `VEX_MODEL_TOKEN`

`VEX_MODEL_TOKEN` must never appear in any config file at any layer. Any
config file containing a `model_token` key is rejected at load time with a
diagnostic naming the file. Set the token via the environment only:

```sh
export VEX_MODEL_TOKEN="your-token-here"
```
