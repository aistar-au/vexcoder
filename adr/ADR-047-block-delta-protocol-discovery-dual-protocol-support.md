# ADR-047: Block-Delta Default, Protocol Discovery, and Dual-Protocol Support

**Status:** Accepted  
**Chain:** ADR-015, ADR-003, ADR-029, ADR-043

## Context

Messages/v1 lacked a default streaming format. Protocol discovery was a request-time probe rather than a cached negotiation, and the runtime had no unified normalization path for block-delta and choices-delta streams.

## Decision

- Messages/v1 uses block-delta format by default: `content_block_start`, `content_block_delta`, `content_block_stop` events.
- Chat-compatible path uses choices-delta: `choices[].delta.tool_calls[]` index-based accumulation.
- `DeltaAccumulator` provides a normalized internal API at `src/runtime/delta_accumulator.rs`.
- `tx_` tool-call ID format generated by `generate_tool_call_id()` in `json_handoff.rs`; accumulator does not self-generate IDs.
- Client-side protocol discovery: probe `POST /v1/messages`, then `POST /v1/chat/completions` with `Accept: text/event-stream`.
- Discovery result cached for the session; `explicit_protocol` config key overrides.
- Bounded per-ID delta queues (capacity 32); TTL cleanup; memory watermark enforcement.
